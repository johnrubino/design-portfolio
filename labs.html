An Agentic Operating System for Life

Navori is a personal AI infrastructure project — a system of specialized agents that work together to manage goals, learning, strategy, and daily priorities.

Dimension Details
Role Solo — Design & Development
Tools Claude, Claude Code, SwiftUI, OpenCLAW
Timeline 12 weeks (and counting)
Status In active development

I'm building this in the open — it's already my daily driver. The backend is mostly stable. The iOS app is in progress. The interesting question isn't "can I build this?" — it's "what should an agentic operating system for a person actually do?"

⚡

Fragmentation & Overwhelm

I was running my life across Notion, Apple Notes, a finance spreadsheet, a reading list, a goal tracker, and a handful of group chats. Everything was technically tracked. Nothing was connected. Every week felt like re-orienting from scratch.

Three problems kept coming up. Context switching costs — by the time I opened the right app and found the right note, the thought was gone. Tools that don't know you — every app starts from zero. No app knows what I care about, what I'm working toward, or what I was thinking yesterday. And an offline-first desire — I don't want to depend on cloud sync for my own thinking. I want it local, fast, and mine.

"I didn't want a smarter to-do list. I wanted something that already knew where I left off — and could help me think."

⚙️

The Framework: OpenCLAW

OpenCLAW (Context-Layered Agent Workflow) is the orchestration layer I built for Navori. Each agent has a specific domain, a persistent memory layer, and a defined relationship to the others. I'm not trying to build one AI that does everything — I'm building a team.

Penn — Life OS Agent
Tracks goals, habits, weekly priorities, and long-term direction. Penn is the connective tissue — it knows what matters and can surface it across contexts.
BNY Strategist — Finance Agent
Manages budgets, tracks spending, models scenarios, and surfaces financial decisions. Connects to Penn so financial goals and life goals aren't siloed.
Design Thinker — Professional Agent
Helps me think through design problems, prepare for client conversations, and synthesize feedback. Persistent memory of past projects means it gets more useful over time.
Learning Assistant — Knowledge Agent
Manages my reading list, synthesizes key ideas from articles and books, and connects new knowledge to active goals. No more reading something important and forgetting it.

"The agents aren't tools you invoke. They're advisors you consult."

💬

Chat Isn't Enough

The first version of Navori ran entirely through Telegram bots. It worked — I used it every day. But the ceiling became obvious fast. A chat thread is a bad UI for anything that benefits from structure: goal tracking, financial summaries, habit streaks. You can't scan a conversation. You can't see patterns. You can't build habits around something that feels ephemeral.

I needed a surface, not a thread. The agents needed a home — somewhere persistent that could show me the state of my life at a glance, not just respond to my queries.

"A chat thread is a river. A dashboard is a lake."

That realization drove the iOS app. The backend agents stay the same. The interface becomes the layer that makes their output legible — morning briefs, goal progress, domain tabs. The chat is still there for when you need to think out loud. But the default view is structure, not conversation.

✨

Key Interface Decisions

The iOS app is organized around two tabs: Today and Agents.

Today is the command center — a morning brief generated by Penn each day, your three active priorities, a Goal Pulse (a compact view of all goals and their momentum), and a quick-capture field. It's designed to be a 60-second daily read.

Agents is where you go deep. Each agent has its own sub-tab: Finance, Design, Learning. Each sub-tab surfaces that agent's persistent output — budget status, reading queue, project notes — and gives you a direct chat interface when you want to go further.

Design system choices
San Francisco system font, adaptive light/dark, 4pt grid. No custom typefaces, no decorative flourishes. The agents are the product — the UI should be invisible.

"A great tool shouldn't feel like productivity software. It should feel like clarity."

🔮

What This Reveals About How I Think

I didn't start with a design brief. I started with a problem I had every morning. The agents came before the interface — I spent the first six weeks just getting the backend right before writing a single SwiftUI view.

That sequencing matters. A lot of AI products start with the chat interface and bolt on "intelligence" later. Navori started with the intelligence and is now building the surface. The result is an app that feels grounded — because every UI decision is driven by what the agents actually produce, not by what a dashboard is supposed to look like.

Speed as a constraint: I built the first working version in ten days using Claude Code almost exclusively. I'm a designer who codes — not a developer who designs. That changes the calculus. I'm not fighting the tooling; I'm using it to compress the gap between idea and artifact.

"The most important design decision wasn't a UI component — it was choosing to build an agent framework before building an interface."

What Navori is really testing is whether agentic interfaces can feel personal instead of generic. Most AI tools feel like they could belong to anyone. Navori is trying to feel like it belongs to me — and through that specificity, become more useful than anything built for everyone.
